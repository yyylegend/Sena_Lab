很多推理参数看起来像需要背诵的命令行选项，但它们其实都在解决有限的硬件资源。

## 约束一：decode 通常受显存带宽影响

生成一个 token 时，模型需要反复读取权重。权重越大，需要搬运的数据越多，decode 越慢。

在本机 RTX 2080 Ti 22GB 上，Qwen3.8-27B 的几组量化结果大致是：

| 模型 / 量化 | 权重 | 理论上限 | 实测 |
| --- | ---: | ---: | ---: |
| Qwen3.8-27B UD-IQ4_XS | 14.4GB | 约 43 tok/s | 33 tok/s |
| Qwen3.8-27B Q4_K_P | 17.92GB | 约 34 tok/s | 32 tok/s |
| Qwen3.6-27B Q4_K_M | 16.8GB | 约 37 tok/s | 22 tok/s |

理论值只是一个检查方向，不是承诺。不同模型结构、后端和采样参数都会改变实测结果。

## 约束二：显存是硬墙

启动时至少要估算：

模型权重 + KV Cache + 固定运行开销。

本机实测固定开销大约在 1.9～2.6GB。显存不足时，后端可能把部分层放到 CPU，程序不一定立刻报错，但速度会明显下降。因此只看“程序能启动”不够，还要看实际 GPU 占用和 tokens/s。

## 约束三：KV Cache 随上下文线性增长

传统全注意力层需要保存历史 token 的 Key 和 Value。上下文越长，KV Cache 越大。

混合架构的模型会用部分线性注意力层降低缓存压力，但全注意力层仍然负责精确检索长上下文里的局部信息。参数 -c、-ctk 和 -ctv，本质上是在上下文长度和 KV 精度之间做取舍。

## 参数怎么推出来

- -ngl 决定有多少层放到 GPU，核心是权重和显存的平衡；
- -c 决定最大上下文长度，直接影响 KV Cache；
- -ctk / -ctv 决定 KV 的存储精度，影响显存和质量；
- draft 相关参数决定是否启用 speculative decoding；
- 采样参数不仅影响文风，也可能改变生成速度。

如果先算清显存账，再看日志里的 GPU 占用和 tokens/s，很多“玄学调参”就会变成可解释的实验。

## 一个重要边界

本机的 temp 从 1.0 调到 0.7 后，速度从 26 tok/s 到 33 tok/s，但这个实验没有完全隔离其他变量，因此我把它记录为观察，不把它写成确定的因果结论。

这也是部署实验最值得保留的部分：把实测、推算和还没有验证的假设分开。
